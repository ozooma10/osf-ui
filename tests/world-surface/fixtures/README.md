# QASmoke world-screen fixture

`OSFUIWorldSurfaceTest.esp` is the unchanged 1,771-byte plugin preserved from
`C:\tmp\osfui-display-screen-proof-passed-20260729\OSFUI.esp`, renamed for the
isolated test profile. The original prototype's transfer notes are preserved in
Git at `6f5b5db^:docs/world-surface-pc-transfer-plan.md`.

The plugin uses only vanilla assets. It places `DisplayScreen5` (Starfield.esm
base FormID `0x000C499F`) in QASmoke (`0x002BE3A9`) at
`(-3.721765, 5.452155, 0.592319)`, rotation `(0, 0, 0)`. Its local reference ID is
`0x81D`. Local material swap `0x816` changes
`SetDressing\DisplayScreens\DisplayScreenWhite1.mat` to
`Architecture\City\NewAtlantis\Lodge\BaseMaterials\NA_Lodge_Space01.mat`.
The plugin also contains an unused earlier Outpost screen material swap.
No custom mesh or loose material file is required.

Run `python tests/world-surface/make-fixture.py --out <isolated-test-mod>` to
stage the plugin and matching 1000x1000 single-mip BGRA8 placeholders at these
vanilla paths:

- `Textures/Architecture/City/NewAtlantis/Lodge/NA_Lodge_Space01_color.DDS`
- `Textures/Architecture/City/NewAtlantis/Lodge/NA_Lodge_Space01_emissive.DDS`

Both textures are generated byte-identically to the historical visual proof.
Their SHA-256 is
`817905FB906C5EE63BA30511DC985B092CA133D91455CAE5D49A4FB1CF9EDD21`.
The plugin SHA-256 is
`63A179B62F89A0DF8AABF3FC56246397605942F9B8FBAEE30976EB4F537C9C2F`.

These overrides also affect vanilla Lodge content while enabled. Keep the
entire fixture in the isolated testing profile; it is excluded from normal
build/deployment/packages. This fixture proves transport and world geometry,
not a release-ready standalone asset. A production screen needs an independently
validated material and its own texture paths. Earlier copied/edited `.mat`
resource graphs broke world rendering even with OSF UI disabled, so this test
deliberately reuses the proven vanilla donor.

The plugin is a display-only snapshot, predating the separate historical
Activator fixture with local IDs `0x825`/`0x826`.
